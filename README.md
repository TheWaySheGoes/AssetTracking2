# Smart Asset Tracking System

A **C# .NET 10 console application** for managing company IT assets across international offices. Created as a mini-project to practice object-oriented programming, **Entity Framework Core**, **SQLite**, **LINQ**, CRUD operations, and reporting.
 
> [!NOTE]
> This is a **console application**, not an ASP.NET Core website or REST API. Currency rates and user roles are simulated for learning purposes.

## Features

- **Asset management:** Create, view, update, and delete laptops, desktop computers, iPhones, Samsung/Nokia devices, and tablets.
- **Asset details:** Brand, model, serial number, purchase date, price in USD, office, optional assigned user, warranty expiration, and maintenance information.
- **Lifecycle tracking:** Three-year lifespan with color-coded **NORMAL**, **RED**, **YELLOW**, and **EXPIRED** statuses.
- **Offices and currencies:** Sweden, USA, Germany, and Turkey with fixed sample exchange rates.
- **Search and filtering:** Find assets by brand, model, office, or purchase year; filter by category or expiration.
- **Reports:** Counts and total value per office, expiring assets, expensive assets, employee assignments, and common asset types.
- **Exports:** Generate **TXT**, **CSV**, or **JSON** files.
- **Employee management:** Add employees and assign or unassign assets.
- **Maintenance tracking:** Record maintenance dates and notes.
- **Demo roles:** Admin, Manager, and Employee with menu-level permissions (**not secure authentication**).

## Getting started

### 1. Clone the repository

```bash
git clone <your-repository-url>
cd <your-repository-folder>
```

Open a terminal in the folder containing **`AssetTracking.csproj`**. If the project is nested in another directory, change into that directory first.

### 2. Restore dependencies

```bash
dotnet restore
```

The `.csproj` file already references `Microsoft.EntityFrameworkCore.Sqlite` and `Microsoft.EntityFrameworkCore.Design`.

### 3. Install EF Core CLI

```bash
dotnet tool install --global dotnet-ef --version 10.0.0
```

If already installed, use `dotnet tool update --global dotnet-ef` instead. The included project pins EF Core packages to **10.0.0**; keeping the CLI and packages on compatible EF Core 10 versions avoids version warnings.

### 4. Create the database

If you **do not already have a `Migrations/` folder**, generate the initial migration:

```bash
dotnet ef migrations add InitialCreate
```

Then apply the migrations:

```bash
dotnet ef database update
```

This creates the SQLite database and tables. Do not create another `InitialCreate` migration if one already exists.

### 5. Run the application

```bash
dotnet run
```

Alternatively, open `AssetTracking.csproj` in Visual Studio and press **Ctrl + F5**.

On first launch, the app seeds four offices and asks you to select a simulated role.

### Creating the project manually in Visual Studio

If you're copying files into a new Visual Studio project instead of cloning the repository:

1. Create a **Console App (C#)** targeting **.NET 10**.
2. Name it **`AssetTracking`** so the namespaces match.
3. Copy the source folders and files into the project, including the supplied `AssetTracking.csproj`.
4. Run the restore, migration, and database update commands above.

## Business rules

- **Lifetime:** Assets expire three years after their purchase date.
- **Statuses:** `EXPIRED` after end of life; `YELLOW` when less than three months remain; `RED` when three to six months remain; `NORMAL` otherwise. This ordering resolves overlapping warning thresholds in the assignment.
- **Prices:** Stored in **USD** and converted to local office currency using fixed example rates, **not live exchange rates**.
- **Unique assets:** Serial numbers are subject to a unique database index.
- **Inheritance:** `Asset` is the base class with `ComputerAsset` and `MobileAsset` subclasses.
- **Roles:** Permissions are simulated through console menus and are **not suitable for production authentication or authorization**.

The SQLite connection is configured as `Data Source=assets.db`. The database file is created relative to the application's current working directory.

## Troubleshooting

| Problem | Solution |
| --- | --- |
| `No project was found` | Run commands in the folder containing `AssetTracking.csproj`, or use `--project <path-to-csproj>`. |
| `Microsoft.EntityFrameworkCore` namespace missing | Run `dotnet restore` and check the package references in `.csproj`. |
| `UseSqlite` is not found | Confirm the `Microsoft.EntityFrameworkCore.Sqlite` package and `using Microsoft.EntityFrameworkCore;`. |
| EF Core Design package missing | Make sure `Microsoft.EntityFrameworkCore.Design` is referenced by the startup project. |
| `No EF Core migration found` | Create the initial migration (if absent) and run `dotnet ef database update`. |
| EF tools version warning | Update `dotnet-ef` to a compatible EF Core 10 version. |
| Database tables missing | Check the working directory and apply migrations to the correct project/database. |

## Project scope

This is an educational mini-project. It does **not** include a web frontend, REST API, production authentication, live currency conversion, or automated tests. The application uses synchronous EF Core operations and a console menu.
